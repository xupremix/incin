# DST-015 - two-rank process rendezvous and launcher

The first launcher target is exactly two processes on network-accessible CUDA
hosts. It establishes run, rank, world, role, and process-local device identity
before CUDA/NCCL communicator creation, then retains a bounded control path for
fail-stop abort and coordinated shutdown.

1. [x] Add `DistributedContext<M, R>` and a cloneable type-erased lifecycle
   handle without making the `distributed` feature require `std`.
2. [x] Seal the static rank contract to `U0` and `U1`, and require every static
   mesh entry point to satisfy `ValidMesh<World = U2>`.
3. [x] Add the matching `Dyn, Dyn` entry point with runtime checks for exact
   world size, rank range, root/peer role, nonzero bounded timeout, and exact
   two-device launch cardinality.
4. [x] Define a bounded nonempty `RunId`, versioned fixed-size startup wire
   record, full run-id comparison, complementary-rank check, and structured
   peer rejection.
5. [x] Keep the rendezvous socket as a control plane after startup, with
   bounded abort propagation and symmetric coordinated shutdown.
6. [x] Add `TwoRankLaunchPlan<M>` with static and `Dyn` rank selection and an
   explicit six-variable environment applied to ordinary `std::process::Command`.
   Device ordinals remain process-local, so `[0, 0]` is valid for two hosts.
7. [x] Implement `DistributedContext<Dyn, Dyn>::from_env()` without hidden
   defaults for identity, cardinality, address, device, or timeout.
8. [x] Bind NCCL topology discovery and communicator creation to the context's
   agreed rank, address, deadline, and local CUDA ordinal.
9. [x] Carry the type-erased fail-stop handle through NCCL launches and
   completion events; any validation, submission, CUDA/NCCL, or timeout error
   invalidates every context clone.
10. [x] Migrate the DP=2, TP=2, and PP=2 two-host harnesses to the shared
    environment launcher, context-bound NCCL setup, and coordinated shutdown.
11. [x] Test a successful static rendezvous, `Dyn` validation failures, missing
    peer timeout, run mismatch, peer abort, shared-handle invalidation, and
    coordinated shutdown.
12. [x] Spawn two real child processes that both use `from_env` and prove
    successful coordinated shutdown rather than only simulating ranks in one
    call stack.
13. [x] Add compile-fail evidence for a static rank outside `U0/U1`, rank one
    attempting to construct a root config, and a static mesh whose world is
    not two.
14. [ ] Run the migrated context-bound NCCL harnesses on two
    network-accessible CUDA hosts and record their fail-stop behavior under an
    injected process or communicator failure.

## Local evidence

```text
cargo test -p incin --features distributed-nccl --test rendezvous
8 passed; 0 failed, including 3 compile-fail cases and 2 child processes

cargo check -p incin-core --no-default-features --features distributed \
  --all-targets
clean
```

The process test uses loopback because a normal CI runner owns only one host.
It proves separate process address spaces, environment parsing, startup
agreement, and shutdown framing; it is not evidence for cross-host
reachability or CUDA/NCCL execution. This row remains active until the final
two-host failure-injection step is recorded.
