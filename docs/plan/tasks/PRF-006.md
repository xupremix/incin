# PRF-006 - `vectorize!` combinator: SIMD coverage for reduce/norm/pool/conv

**Theme:** perf  
**Tier:** performance  
**Deps:** PRF-003, PRF-004

Introduces a `vectorize!` higher-order combinator in `incin-backends` that
processes data in `simd_lanes::<T>()` chunks using `std::simd`, with an
automatic scalar tail. Uses this to give SIMD coverage to the ~9 000 lines of op
code that currently have none: reduce, norm, pool, and the conv inner loop.

## Benchmark - before

```bash
cargo bench -p incin --bench baselines -- \
  'eager/sum_f32' \
  --save-baseline prf006-before
```

Also time manually:
```bash
# Warm up with a large reduction to see scalar vs SIMD difference
cargo test -p incin-backends --release -- reduce 2>&1 | tail -5
```

Save to `docs/plan/baselines/prf006-before.txt`.

## Steps

1. [x] Add `pub fn vectorize<T, const N: usize>(len, f)` to
   `crates/incin-backends/src/simd.rs` (alongside `simd_lanes`). The function:
  - Processes `len / N` full SIMD chunks using `std::simd::Simd::<T, N>`
  - Processes the remaining `len % N` elements in a scalar tail
  - `N` is a const parameter, resolved by callers as `simd_lanes::<T>()`
2. [x] Add `pub fn vectorize_reduce<T, const N: usize>(len, init, f_simd,
   f_scalar, reduce)` for reduction operations (sum, max, min, norm) that need
   to accumulate a SIMD vector and then fold it to a scalar.
3. [x] Replace the scalar loops in:
  - `reduce.rs` (`sum`, `mean`, `max`, `min`, `norm`) - these are entirely
     scalar today; expected **3–8×** gain
  - `norm.rs` (layer norm, batch norm) - scalar today
  - `pool.rs` (avg pool, max pool) - scalar today
4. [x] Add a vectorised path to the conv2d inner accumulation loop (the per-
   output-channel dot product over `kh × kw × in_c`), using `vectorize_reduce`.
5. [x] Write benchmarks for the newly covered ops in `baselines.rs`:
  - `eager/sum_f32/65536` (already exists - compare before/after)
  - `eager/sum_f32/1048576` (new - large enough to show cache behaviour)
6. [x] Run `cargo test --workspace`. Gradient-parity tests for all affected ops
   must pass.

## Benchmark - after

```bash
cargo bench -p incin --bench baselines -- \
  'eager/sum_f32' \
  --save-baseline prf006-after

cargo bench -p incin --bench baselines -- \
  'eager/sum_f32' \
  --load-baseline prf006-before \
  --baseline prf006-after
```

**Expected:**
- Reduce (sum/mean/max) on f32: **3–8×** (currently pure scalar loop)
- Norm (layer/batch) on f32: **3–6×**
- Pool (avg/max): **2–4×**
- Conv inner loop: **2–4×** (combined with PRF-005 tiling: up to 8×)

## Boundaries

The AVX2-intrinsic paths in `elementwise_kernel.rs` for binary ops are not
removed - they are hand-tuned and faster than `std::simd` on AVX2 for the
specific binary op pattern. `vectorize!` covers the currently-unserved ops.
