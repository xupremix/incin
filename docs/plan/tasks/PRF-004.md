# PRF-004 — `TypedKernel<T>` dispatch: eliminate f64 widening in unary ops

**Theme:** perf  
**Tier:** performance  
**Deps:** PRF-003

Eliminates the `get_f64` / `from_f64_values` round-trip that every elementwise
unary op (relu, sigmoid, gelu, tanh, …) currently performs regardless of the
actual storage dtype. Every bf16/f16/f32 element is currently widened to f64,
computed, then narrowed back — preventing both native-dtype SIMD and hardware
bf16 arithmetic. This is the highest-impact correctness→performance fix in the
CPU backend.

## Benchmark — before

```bash
# Add a bf16 unary benchmark if not present, then:
cargo bench -p incin --bench baselines -- \
  'eager/(add_f32|sum_f32)' \
  --save-baseline prf004-before
```

Also measure manually for the affected ops at warmup:

```bash

```

Save results to `docs/plan/baselines/prf004-before.txt`.

## Steps

1. [ ] Introduce a `TypedKernel<T: DType>` trait in
   `crates/incin-backends/src/cpu/typed_kernel.rs` with a single method:
   ```rust
   fn map_unary(input: &[T], output: &mut [T], f: impl Fn(T) -> T + Send + Sync);
   ```
2. [ ] Implement `TypedKernel` for `f32`, `f64`, `bf16`, `f16`, `u8`, `i8`,
   `u32`, `i32` with a straight scalar loop first (no f64 widening).
3. [ ] For `f32` and `f64`, add a SIMD fast path using `simd_lanes::<T>()` from
   PRF-003 and `std::simd::Simd<T, LANES>` to process N elements per iteration.
4. [ ] Refactor `elementwise_unary` in `elementwise.rs` to call
   `TypedKernel::<T>::map_unary` instead of `get_f64` / `from_f64_values`.
   The dispatch now happens at the trait impl level, fully visible to the
   compiler.
5. [ ] Repeat for `elementwise_binary` → `TypedKernel<T>::map_binary`.
6. [ ] Ensure backward closures (grad computation) also use typed paths.
7. [ ] Run `cargo test --workspace`. All existing gradient-parity tests must
   still pass (they validate numerical correctness of the unary ops).

## Benchmark — after

```bash
cargo bench -p incin --bench baselines -- \
  'eager/(add_f32|sum_f32)' \
  --save-baseline prf004-after

cargo bench -p incin --bench baselines -- \
  'eager/(add_f32|sum_f32)' \
  --load-baseline prf004-before \
  --baseline prf004-after
```

Add new series to `baselines.rs` before running:
- `eager/relu_f32/65536`
- `eager/relu_bf16/65536` ← this is the key one

**Expected:**
- f32 unary ops: **2–3×** faster (eliminates f32→f64→f32 per element)
- bf16 unary ops: **4–8×** faster (was widening to f64 and back; now native)
- Compiler auto-vectorisation rate increases from ~0% to ~60–80% for unary ops

## Boundaries

Binary ops that use AVX2 intrinsics directly (`avx2_binary_f32` etc.) are not
touched here; they already bypass the f64 widening. This row covers the scalar
and typed paths only. The `vectorize!` combinator macro (PRF-006) builds on top
of this.
