# TUN-004 - `#[autotune(...)]` proc-macro attribute

**Theme:** tune  
**Tier:** performance  
**Deps:** TUN-003, PRF-005

Exposes the existing autotune service through a `#[autotune(params = [...])]`
proc-macro attribute in `incin-macros`, making it a one-liner at the call site.
Currently the tuning infrastructure (TUN-001–003) is correct and battle-tested
but requires callers to know about `TuningService` and wire it up manually - 
meaning in practice no production code uses it and every user runs untuned tile
sizes.

## Benchmark - before

```bash
cargo bench -p incin --bench baselines -- \
  'eager/matmul_f32' \
  --save-baseline tun004-before
```

Also record the current `SIMD_PARALLEL_CHUNK` constant value and the tile
size default from `scalar_gemm` in `docs/plan/baselines/tun004-before.txt`.

## Steps

1. [x] Add a `#[proc_macro_attribute]` named `autotune` to `incin-macros`.
   Attribute syntax:
   ```rust
   #[autotune(
       key   = "matmul_f64_tile",    // cache key suffix
       params = [(32,32), (64,64), (128,64)],
       policy = heuristic,           // disabled | heuristic | warmup | profile
   )]
   fn matmul_tiled(m, k, n, ...) { ... }
   ```
2. [x] The macro wraps the annotated function body in a dispatch shim that:
  - On first call: reads the autotune cache; if cold, selects via the
     `policy` and runs a short sweep over `params`; writes the winner.
  - On subsequent calls: reads the cached winner and dispatches directly.
3. [x] Apply `#[autotune(...)]` to `scalar_gemm` in matmul.rs and to the
   tile-selection call in conv.rs (added in PRF-005).
4. [x] Apply to `SIMD_PARALLEL_CHUNK` selection in `elementwise_kernel.rs` - 
   make it a tuned choice over `[4096, 8192, 16384, 32768]` rather than a
   single compile-time constant.
5. [x] Add compile-fail evidence in `crates/incin-macros/tests/compile_fail/`
   for: `params` list empty, `policy` invalid keyword, `key` empty string.
6. [x] Run `cargo test --workspace --features autotune`.

## Benchmark - after

```bash
# Let the warmup sweep run once:
cargo bench -p incin --bench baselines -- \
  'eager/matmul_f32' \
  --save-baseline tun004-warmup

# On a second run (should use cached winner):
cargo bench -p incin --bench baselines -- \
  'eager/matmul_f32' \
  --save-baseline tun004-after

cargo bench -p incin --bench baselines -- \
  'eager/matmul_f32' \
  --load-baseline tun004-before \
  --baseline tun004-after
```

**Expected:**
- Matmul tile: **20–40%** mean throughput gain on hardware where the default
  tile doesn't fit L2
- Conv tile: **15–30%**
- `SIMD_PARALLEL_CHUNK`: **10–20%** for large reductions
- Cold-start cost: **−5–15% on first run** (warmup sweep) - cached thereafter

## Boundaries

The autotune service itself (TUN-003) is not modified. This row is purely an
ergonomic wrapper. The `autotune` feature gate remains required; calling the
macro without the feature produces a compile error rather than a silently
untuned function.
