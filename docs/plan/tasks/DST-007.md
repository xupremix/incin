# DST-007 - collective plans and preflight agreement

`DST-003` proves which placement movements are legal and `DST-005` proves what
each collective computes. This row joins them into an immutable launch order
whose ranks can compare every invariant before entering a communicator.

1. [x] Consolidate the transport-neutral collective vocabulary in
   `incin-core::dist::collective`; preserve backend paths through re-exports.
2. [x] Add `CollectiveDescriptor` with group identity/cardinality, operation
   and reduction, checked input/output elements and bytes, dtype,
   source/destination placements, sequence token, stream, and dependency.
3. [x] Add `CollectivePlanBuilder` tied to a bound `DeviceMesh`.
   `push_static` requires `ConstDType + CollectiveDType`, `LegalTransition`,
   and `PlacementOn` for the same mesh.
4. [x] Add `push_dyn`, which validates runtime dtype and placement transition
   before entering the same descriptor construction path.
5. [x] Derive all-gather and reduce-scatter counts from group cardinality,
   reject non-divisibility and overflow, and pin both movements to the tensor
   communicator.
6. [x] Assign monotonic `SequenceToken` values and accept dependencies only on
   earlier tokens in the same order.
7. [x] Hash the mesh and every descriptor field with a stable versioned digest.
   Add `PlanSummary`, all-rank `preflight`, and sealed `AgreedPlan`.
8. [x] Prove count, hash, mesh, rank, dependency, axis, dtype, and transition
   failures at runtime; prove Q8, cross-mesh placement, and illegal transition
   failures at compile time.
9. [x] Prove two `ProcessPerRank` views of two network-linked CUDA ranks derive
   one mesh identity, one plan identity, and successful preflight.
10. [x] Run feature tests, no-std checking, clippy, rustdoc, workspace tests,
    and repository policy gates.

## Boundaries

Preflight compares summaries; it does not exchange them. Core is `no_std` and
cannot open a socket or initialize NCCL. DST-006 transports the summary for the
two-node CUDA path and DST-015 owns the general rendezvous/launcher.

All-to-all remains implemented and tested by the reference transport, but
`CollectivePlanBuilder` does not fabricate a placement meaning for it.
`DST-003` has no all-to-all transition yet; a planner method without one would
accept source and destination semantics no proof established.

`PlacementKind` deliberately contains no `MeshId`. Static endpoints therefore
also require `PlacementOn<M>`, tying them to the builder's bound mesh at
compile time. `Dyn` endpoints acquire the builder's mesh identity at the
checked runtime boundary.

## Outcome

Every message count and byte count is decided once. A rank cannot independently
infer a different count, dtype, group, ordering token, or dependency and still
pass preflight. Static programs reject unsupported dtype/placement/mesh
combinations in trait resolution; `Dyn` reports the corresponding structured
runtime error before any transport launch.
