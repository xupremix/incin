# EXE-007 - CPU descriptor-execution vertical slice

1. [x] Audit the roadmap sequencing, descriptor semantics, CPU storage and
   matmul implementation, autograd tape behavior, and public construction
   surface. Select matrix multiplication as the complete vertical slice:
   `MatMulSpec` fully determines its operation, and PRF-002 depends on this
   row; reduction and pooling descriptors deliberately omit their reduction
   mode and must not be assigned invented semantics.
2. [x] Make `CpuBackendImpl<T, D>` explicitly constructible and implement
   `StorageBackend<Local>` with `CpuStorage` and its checked `TensorMeta`.
3. [x] Add a CPU request binder that requires exactly two `CpuStorage` inputs,
   checks CPU/F32 resource metadata against the sealed `MatMulSpec`, and
   returns structured `BackendError` values before dispatch.
4. [x] Implement only `Execute<MatMulSpec>` for the CPU backend, delegating to
   the existing rank-2/batched kernels so forward and tape behavior remain
   identical. Do not add blanket executors or claim geometry-only descriptors.
5. [x] Add parity coverage for rank-2, batched/broadcast, strided-view, and
   backward behavior against the legacy CPU path, plus exact rejection tests
   for wrong input count, storage type, dtype/device, and descriptor binding.
6. [x] Record deterministic request-layer footprint/allocation facts and a
   non-gating repeated-run timing comparison against the legacy entry point;
   do not turn noisy wall-clock timing into a correctness gate.
7. [x] Run the row evidence plus formatting, Clippy, core/workspace tests,
   no-default-features, optional backend compile checks, rustdoc, diff-check,
   shape audit, budgets, and ledger validation.
8. [x] Record concrete evidence and justified deviations before completing
   EXE-007 and activating EXE-008.
