# DST-004 - placement-aware tensor metadata

`DST-003` proves global and rank-local placement metadata, but its proof did not
own storage. This row joins that seal to the one tensor type without imposing
distributed overhead on ordinary local tensors.

1. [x] Extend `Tensor` to `Tensor<S, B, K, G, P = Local>` while preserving the
   existing four-parameter spelling and local constructor surface.
2. [x] Make the typed shape field global and the backend storage rank-local.
   Expose both `dims()` and `local_dims()` so neither meaning is implicit.
3. [x] Store placement through `P::Field`: zero-sized for `Local`, rank-only for
   static distributed placements, and `PlacementKind` plus rank for `Dyn`.
4. [x] Add the only safe placed constructor. It requires
   `SupportsDType<K>` and a sealed `ValidatedDistributed` proof, then checks
   global shape, output placement, rank, local shape, dtype, and device.
5. [x] Add static `try_reshard<To>`, gated by `LegalTransition<To>`, and the
   `Dyn` counterpart using `validate_transition`.
6. [x] Prove illegal static transitions with trybuild and prove the corresponding
   dynamic rejection and all metadata mismatch variants at runtime.
7. [x] Forward the distributed feature through the facade and add the preview
   evidence command to CI.
8. [x] Run feature-specific tests, no-std checking, lints, rustdoc, workspace
   tests, and repository policy gates.

## Boundaries

Local constructors do not accept a placement parameter. A distributed tensor
is not storage with an annotation; it is storage whose global/local relation
has already been proved.

`Dyn` is not a bypass. It moves shape, dtype, device, and placement decisions to
runtime and therefore checks all four before construction. The static spelling
keeps the same rules as trait bounds and zero-sized/static fields.

This row does not execute a collective. Resharding verifies that replacement
storage and the sealed transition agree; DST-005 supplies transport operations
and DST-007 supplies executable ordering.

## Outcome

The placement parameter is defaulted, so existing local code remains unchanged.
Static distributed tensors carry only the fact that cannot be encoded in their
type - the rank - while `Dyn` carries and validates the runtime placement. The
placement tensor suite has eight passing tests, including a compile-fail case,
and explicitly proves that `Local::Field` remains zero-sized.
