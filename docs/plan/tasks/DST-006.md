# DST-006 — two-host NCCL transport

The first native distributed transport is exactly two CUDA ranks in separate
processes on network-accessible hosts. One process owns one local CUDA buffer;
NCCL supplies the peer rank over the network.

1. [x] Add the opt-in `distributed-nccl` backend and facade features without
   adding NCCL to default or reference-only builds.
2. [x] Add `NcclTopology` with real local CUDA UUID/compute-capability probing,
   real NCCL version probing, `ProcessPerRank`, and a network link.
3. [x] Exchange the two physical identities and transport versions over a
   bounded, versioned TCP protocol before either rank binds a mesh.
4. [x] Exchange the NCCL unique id and `PlanSummary` over a second bounded TCP
   protocol; call core `preflight` before `ncclCommInitRank`.
5. [x] Bind `NcclTransport` to one immutable agreed plan and require every
   launch to consume the next `SequenceToken`.
6. [x] Validate group cardinality, runtime dtype, logical element count,
   physical byte count, and reduction semantics before allocation or launch.
7. [x] Dispatch all-reduce, all-gather, reduce-scatter, and two-rank all-to-all
   over NCCL scalar types; return a CUDA event with bounded waiting.
8. [x] Keep static and runtime policy paired: `CollectiveDType` rejects Q8 at
   compile time, while `Dyn` checks the same dtype and descriptor at runtime.
9. [x] Add CPU-runnable tests for identity/version exchange, plan divergence,
   order/count/dtype/byte drift, corrupt protocol, timeouts, and sequential
   discovery/plan handshakes.
10. [x] Add a two-host ignored hardware harness that runs static `f32` and
    `Dyn/F64` all-reduce through the complete discovery, mesh, plan, bootstrap,
    communicator, event, and readback path.
11. [ ] Run the hardware harness concurrently on two network-accessible CUDA
    hosts with NCCL installed and record successful values plus induced
    missing-rank/failure evidence.

## Hardware command

On rank zero:

```text
INCIN_DIST_RANK=0 INCIN_DIST_BIND=0.0.0.0:29500 \
  cargo test -p incin-backends --features distributed-nccl \
  --test nccl_two_rank -- --ignored --exact two_networked_cuda_ranks_static_and_dyn
```

On rank one, replacing the address with rank zero's reachable address:

```text
INCIN_DIST_RANK=1 INCIN_DIST_ROOT=10.0.0.10:29500 \
  cargo test -p incin-backends --features distributed-nccl \
  --test nccl_two_rank -- --ignored --exact two_networked_cuda_ranks_static_and_dyn
```

`INCIN_DIST_DEVICE` defaults to local CUDA ordinal zero. Both hosts discover
their UUID, architecture, and NCCL version themselves; no ordinal is treated
as a persistent cross-host identity.

The current communicator executes the immutable plan in strict sequence on
one CUDA stream. `StreamId` remains attached to events for dependency
diagnostics, but distinct logical ids do not yet create concurrent physical
streams. This is conservative and correct; coordinated stream scheduling is a
later optimization rather than an ordering claim.

## Current evidence boundary

All code, compile-fail policy, TCP behavior, metadata validation, facade wiring,
and the hardware test target compile and pass their CPU-runnable gates. This
machine has one CUDA GPU and no NCCL shared library, so it cannot truthfully
complete the final two-host row. DST-006 remains planned until the exact
hardware command succeeds on both hosts.
