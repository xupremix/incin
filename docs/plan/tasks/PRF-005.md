# PRF-005 - `tile_2d` cache-blocking utility + autotune integration

**Theme:** perf  
**Tier:** performance  
**Deps:** PRF-003, TUN-003

Adds a `tile_2d<const TX: usize, const TY: usize>` loop-blocking utility to
`incin-backends::iteration` and uses it in `scalar_gemm` (matmul.rs) and the
conv2d inner loop (conv.rs). These are currently triple scalar loops with no
cache blocking: a 512×512 f64 matmul achieves ~3 GFLOP/s where 15+ GFLOP/s is
achievable. The autotune service (TUN-003) selects the tile size per topology.

## Benchmark - before

```bash
# Extend baselines.rs to include f64 and larger matmuls before running
cargo bench -p incin --bench baselines -- \
  'eager/(matmul_f32|batched_matmul_f32)' \
  --save-baseline prf005-before
```

Also add and run manually:

## Steps

1. [ ] Add `pub fn tile_2d<const TX: usize, const TY: usize>(rows, cols, f)` to
   `crates/incin-backends/src/iteration.rs`. The function decomposes an
   `(rows × cols)` loop into `(TX × TY)` tiles, calling `f(r0, r1, c0, c1)` per
   tile. Handle the boundary tiles (last row/col may be smaller than TX/TY).
2. [ ] Replace the triple scalar loop in `scalar_gemm` (matmul.rs) with a
   `tile_2d`-driven kernel. Start with `TX = 64, TY = 64` as the default (fits
   a 512 KB L2 for f32; halve for f64).
3. [ ] Add the same tiling to the conv2d output-pixel loop in conv.rs. The tile
   covers the `(out_h × out_w)` axes; the inner `(kh × kw × in_c)` loop stays
   as-is.
4. [ ] Hook the tile selection into the autotune service: define a
   `TileKey { m, n, k, dtype }` cache key and a `[TX, TY]` candidate list
   `[(32,32), (64,64), (128,64), (64,128)]`. On first call without a cached
   winner, run the heuristic (choose based on `simd_lanes::<T>() * 8`); on
   warmup, profile all candidates and persist the winner.
5. [ ] Write `crates/incin-backends/tests/tiling.rs` verifying that `tile_2d`
   covers every element exactly once for square, rectangular, and non-multiple
   shapes.
6. [ ] Run `cargo test --workspace`. Gradient-parity tests for matmul must pass
   unchanged (they check correctness of the tiled result).

## Benchmark - after

```bash
cargo bench -p incin --bench baselines -- \
  'eager/(matmul_f32|matmul_f64|batched_matmul_f32)' \
  --save-baseline prf005-after

cargo bench -p incin --bench baselines -- \
  'eager/(matmul_f32|matmul_f64|batched_matmul_f32)' \
  --load-baseline prf005-before \
  --baseline prf005-after
```

**Expected:**
- `scalar_gemm` f64 (512×512): **3–6×** (cache miss rate drops from ~60% to <5%)
- `scalar_gemm` f32 strided (non-BLAS path): **2–4×**
- Conv2d untiled scalar: **3–8×** depending on kernel size

## Boundaries

`blocked_gemm` (the BLAS path, `cpu-blas` feature) is already cache-optimal and
is not modified. This row covers the pure-Rust scalar fallback only.
