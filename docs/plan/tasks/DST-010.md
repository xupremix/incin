# DST-010 — PP=2 networked GPipe and 1F1B

The first pipeline topology is exactly two ranks in separate processes on
network-accessible CUDA hosts. The current executable fixture validates plan
construction and NCCL communicator setup; CUDA tensor-kernel parity is
covered by backend-specific capability tests.

1. [x] Define `TwoRankPipeline` as
   `MeshSpec<Data<U1>, TensorParallel<U1>, Pipeline<U2>>`.
2. [x] Define `PipelineDType`: `f16`, `bf16`, `f32`, `f64`, and `Dyn`.
   Static integer/quantized values are compile errors; `Dyn` rejects the same
   runtime dtypes.
3. [x] Select static activation shape, nonzero typenum microbatch count, and
   schedule through types; validate runtime shape cardinality, nonzero count,
   overflow, dtype, and schedule through the `Dyn` builder.
4. [x] Describe each boundary crossing as one global
   `SendRecv { source, destination }` operation so both ranks hash identical
   peer metadata. Encode boundary identity, microbatch, and direction in the
   semantic plan tag.
5. [x] Generate explicit two-stage GPipe and 1F1B clock timelines with
   warmup/steady/cooldown counts, bubble slots, and peak live activations.
6. [x] Prove deterministic forward-output and weight-gradient parity on the
   reference transport for static `f32` GPipe and `Dyn(F64)` 1F1B.
7. [x] Add typed CUDA tensor execution that validates identity, direction,
   microbatch, placement, dtype, count, bytes, device, layout, and sequence
   before native NCCL `send`/`recv`.
8. [x] Compile a two-host facade harness that mixes static and `Dyn(F32)`
   microbatches and run its local CUDA forward and gradient math.
9. [ ] Integrate the schedule with immutable compiled execution once its
   dependency CMP-002 lands.
10. [ ] Run the full ignored harness concurrently on two network-accessible
    CUDA/NCCL hosts and record both ranks' parity and missing-rank/failure
    behavior.

## Local evidence

```text
cargo test -p incin-core --features distributed --test pipeline
5 passed; 0 failed, including 4 compile-fail cases

cargo test -p incin-backends --features distributed-reference \
  --test pipeline_reference
2 passed; 0 failed

cargo test -p incin-backends --features distributed-nccl \
  pipeline_preflight_requires_identity_direction_and_dyn_float_dtype
1 passed; 0 failed

cargo test -p incin --features distributed-nccl,hardware-tests --test pp2_network \
  -- --ignored --exact pp2_plan_and_communicator_initialize
1 passed; 0 failed

cargo test -p incin --features distributed-nccl,hardware-tests --test pp2_network --no-run
compiled
```

The compile-fail cases reject integer payloads, zero or unencodable static
microbatch counts, and a DP=2 mesh. Runtime tests reject all
integer/quantized dtypes, zero
microbatches, shape-product overflow, bad ranks, boundary identity drift,
direction drift, and payload count drift. Static and `Dyn` plans with equal
values produce the same hash; changing GPipe to 1F1B changes transfer order and
is rejected by preflight before communicator creation.

For four microbatches both two-stage schedules expose four unavoidable idle
stage slots. GPipe retains four activations per stage; the implemented 1F1B
timeline retains at most two on stage zero and one on stage one.

## Required two-host evidence

```text
# host 0
INCIN_RANK=0 INCIN_WORLD_SIZE=2 INCIN_RUN_ID=pp-example \
INCIN_LOCAL_CUDA_DEVICE=0 INCIN_RENDEZVOUS_ADDR=0.0.0.0:29530 \
INCIN_RENDEZVOUS_TIMEOUT_MS=30000 \
cargo test -p incin --features distributed-nccl,hardware-tests --test pp2_network \
  -- --ignored --exact pp2_static_and_dyn_match_single_device

# host 1
INCIN_RANK=1 INCIN_WORLD_SIZE=2 INCIN_RUN_ID=pp-example \
INCIN_LOCAL_CUDA_DEVICE=0 INCIN_RENDEZVOUS_ADDR=<host-0-ip>:29530 \
INCIN_RENDEZVOUS_TIMEOUT_MS=30000 \
cargo test -p incin --features distributed-nccl,hardware-tests --test pp2_network \
  -- --ignored --exact pp2_static_and_dyn_match_single_device
```

Rank one must reproduce the one-device stage outputs, and rank zero must
reproduce the complete stage-zero weight gradient for static and runtime
`Dyn(F32)` microbatches. Until that output exists and CMP-002 supplies the
compiled-plan integration point, DST-010 remains active rather than complete.
