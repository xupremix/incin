# TUN-006 - GEMM and convolution library-versus-native tuning with a crossover report

**Theme:** tune  
**Tier:** preview  
**Deps:** TUN-005

Extends the CUDA autotuning infrastructure to select between native CUDA tile kernels and vendor library paths (`cuBLAS`, `cuDNN`) for MatMul (GEMM) and Conv2d operations, recording crossover thresholds based on matrix shapes and channels.

## Steps

1. [x] Extend `crates/incin-backends/src/cuda/ops/matmul.rs` to support `MatMulTileCandidate` candidate selection and tuning integration.
2. [x] Extend `crates/incin-backends/src/cuda/ops/conv.rs` to support Conv2d algorithm/tile candidate selection and tuning integration.
3. [x] Implement candidate pruning using `prune_matmul_candidates` from `crates/incin-backends/src/tuning/signature.rs`.
4. [x] Write unit tests verifying MatMul candidate pruning and candidate fallback when hardware libraries are unavailable.
5. [x] Run `cargo test -p incin-backends --test tuning_pruning --features autotune`.

## Boundaries

Covers GEMM (MatMul) and Conv2d kernel and vendor library selection.
