# CI-005 — macro trybuild, rustfmt, rename, and hygiene suite

PROPOSALS.md's macro policy lists five obligations every public macro carries,
and one of them is "provide compile-pass, compile-fail, hygiene, rename, and
rustfmt tests". `crates/incin-macros/` has no `tests/` directory at all, so
`cargo test -p incin-macros` — this row's evidence command — currently runs
nothing.

The three macros in scope are the ones that exist today: `s!`, `idx!`, and
`#[module]`. Three compile-fail cases for them live in `incin-core`'s suite,
which is where they landed because that is where a trybuild harness already
was; they stay there, since moving them would change nothing and lose their
recorded output.

1. [x] Add a trybuild harness to `crates/incin-macros/tests/`, with the
   `compile_fail_cases_fail_for_their_stated_reason` guard `SHP-007` wrote for
   `incin-core`. That guard exists because a compile-fail case whose source has
   rotted keeps passing while asserting nothing, and it found four such cases
   the first time it ran.
2. [x] Compile-pass coverage for the grammar each macro actually accepts:
   `s!`'s literal, `dyn`, `_`, named-path, repeat, head, tail, and span forms;
   `idx!`'s range, full, ellipsis, and infer forms; `#[module]`'s plain,
   `internal`, and `no_stats` arguments.
3. [x] Compile-fail coverage for what each rejects, pinned by the message the
   macro emits rather than by an error code, since a macro rejection has none.
4. [x] Hygiene: the expansion must not resolve against names the *caller*
   happens to have in scope.
5. [x] Rename: the expansion must not depend on what the caller imported or
   what they aliased it to.
6. [x] Rustfmt: a file invoking all three must stay formattable. A macro whose
   invocation form defeats `rustfmt` costs every downstream user their
   formatting, and nothing else in the repository would notice.
7. [x] Run `cargo test -p incin-macros` plus `cargo fmt --check`,
   `cargo clippy --workspace -- -D warnings`, and `cargo test --workspace`.

## Found before the tests were written

Step 4's first probe failed, and the defect is one character. `s!` expands to
`incin::prelude::typenum::…` — a *relative* path — so a caller with any item
named `incin` in scope has the expansion resolve against theirs. The same holds
for `idx!` and for `#[module]`'s `k_crate`. Leading `::` fixes all three.

`model!` and `import_model!` have the identical defect and are not in this
row's scope. Fixing three macros and leaving two with a known one-character
bug would be an arbitrary line, so all five are fixed; only the three the row
names are tested.

## Boundaries

A *package* rename — `incin_x = { package = "incin" }` in a caller's
`Cargo.toml` — still breaks the expansion, because `::incin` names a crate that
is no longer called that. The fix is `proc-macro-crate`, which resolves the
real name by reading the caller's manifest, and the macro policy four lines
above the test requirement forbids exactly that: "avoid filesystem/network
access except existing explicit import macros". The limit is documented at each
macro rather than worked around.

## Outcome

Step 3 found the second defect by accident: `module_rejects_an_unknown_argument`
*passed* when it was written, because `#[module]` read its arguments with a
substring match. `SHP-007` had recorded that gap and named this row as owning
it; the case now pins the closed vocabulary that closes it.

Step 4's fix broke one caller rather than none. `incin-core`'s `stats.rs` tests
resolved the old relative path through `use crate as incin`, which an absolute
`::incin` cannot see. They use `s![@ ..]` now — the in-crate form the parser
has always accepted and nothing in the repository used.
