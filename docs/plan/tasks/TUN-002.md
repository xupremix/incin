# TUN-002 - Atomic bounded persistent tuning cache

1. [x] Store schema, creation time, measurement method, sample count, median,
   environment-bound key, legal-candidate digest, and opaque winner.
2. [x] Checksum the canonical known-field body while tolerating unknown fields.
3. [x] Quarantine malformed JSON, schema mismatch, checksum failure, duplicate
   keys, and invalid imported records.
4. [x] Take a cross-process lock and reload/merge before every write.
5. [x] Write a create-new sibling temporary, fsync it, atomically rename it,
   and fsync the parent directory.
6. [x] Enforce age, record-count, and serialized-byte bounds with deterministic
   oldest-first eviction.
7. [x] Refuse a single oversized record without replacing the last valid file.
8. [x] Require current legal-candidate digest agreement on lookup.
9. [x] Provide static and `Dyn` cache keys with checked backend projection and
   compile-fail evidence.

## Evidence

```text
cargo test -p incin-backends --features autotune --test tuning_cache
9 passed; 0 failed
```

The suite covers concurrent process views, atomic round trip, corruption,
schema/checksum recovery, unknown fields, age/count/byte eviction, provenance,
untrusted legality, and one trybuild case.
