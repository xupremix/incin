# PRF-003 — `simd_lanes<T>()` compile-time lane-width constant

**Theme:** perf  
**Tier:** performance  
**Deps:** PRF-001, PRF-002

Introduces a `const fn simd_lanes<T: Sized>() -> usize` in `incin-backends`
that resolves to the correct SIMD vector width for type `T` on the compile
target, replacing the runtime `is_x86_feature_detected!("avx2")` guards that
currently block the compiler from vectorising across the branch.

## Benchmark — before

Run and record before touching any code:

```bash
cargo bench -p incin --bench baselines -- \
  'eager/(add_f32|sum_f32|matmul_f32)' \
  --save-baseline prf003-before
```

Save the output to `docs/plan/baselines/prf003-before.txt`.

## Steps

1. [ ] Add `pub const fn simd_lanes<T: Sized>() -> usize` to
   `crates/incin-backends/src/simd.rs` (new file). Use nested
   `#[cfg(target_feature)]` — `avx512f` (64 B), `avx2` (32 B),
   `sse4.1` (16 B), `neon` (16 B), fallback (1). Do **not** use
   `is_x86_feature_detected!`; that is a runtime call.
2. [ ] Export `simd_lanes` from `crates/incin-backends/src/lib.rs` behind
   no feature flag (it is a `const fn` with zero overhead).
3. [ ] Replace the two runtime `is_x86_feature_detected!("avx2")` guards in
   `elementwise_kernel.rs` with a `const LANES: usize = simd_lanes::<f32>();`
   and a `if LANES >= 8 { ... }` branch. The compiler now sees a compile-time
   constant and can eliminate the dead branch entirely.
4. [ ] Add `simd_lanes::<f16>()`, `simd_lanes::<bf16>()`, `simd_lanes::<f64>()`
   variants (halve/double the f32 lane count where the type is wider/narrower).
5. [ ] Write unit tests in `crates/incin-backends/tests/simd_lanes.rs` asserting
   lane counts are positive, divide 64, and are ≥ 1 for every dtype.
6. [ ] Run `cargo test --workspace` and `cargo clippy --workspace --all-targets
   -- -D warnings`.

## Benchmark — after

```bash
cargo bench -p incin --bench baselines -- \
  'eager/(add_f32|sum_f32|matmul_f32)' \
  --save-baseline prf003-after

# Compare
cargo bench -p incin --bench baselines -- \
  'eager/(add_f32|sum_f32|matmul_f32)' \
  --load-baseline prf003-before \
  --baseline prf003-after
```

**Expected:** 10–30% latency reduction on ops that currently hit the runtime
branch guard. On AVX-512 hardware the gain is 2× (lane width doubles). On
machines without AVX2, the scalar path is now selected statically and the branch
cost disappears.

## Boundaries

This row adds the constant and wires it into the elementwise guard. The
`vectorize!` combinator (PRF-004) and typed-kernel dispatch (PRF-005) consume it
in later rows.
