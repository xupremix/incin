# GRD-004 — CUDA and WGPU gradient parity

GRD-003 moved the reverse walk and tensor identity into `incin-core`; this row
proves that the device-specific recipes feeding that contract compute the same
forward values and gradients as the independent CPU implementation.

1. [x] Exercise WGPU elementwise, activation, normalization, matrix
   multiplication, convolution, pooling, reduction, and loss recipes against
   CPU.
2. [x] Exercise CUDA elementwise, matrix multiplication, normalization, and
   convolution recipes against CPU on real CUDA hardware.
3. [x] Read results through the public `Backend::to_bytes` and gradients through
   `Backend::get_grad`, so the test covers the backend contract rather than
   private buffers.
4. [x] Keep the shared reverse-walk tests active under both feature sets.
5. [x] Run the WGPU evidence command and the ignored CUDA hardware cases
   serially.

## Evidence

```text
cargo test -p incin-backends --features wgpu --lib \
  -- --test-threads=1
22 passed; 0 failed

cargo test -p incin-backends --features cuda --lib \
  -- --ignored --test-threads=1
4 passed; 0 failed
```

The CUDA cases ran on the locally available NVIDIA GTX 1650 SUPER. The WGPU
suite initialized the available WGPU adapter and completed all device
readbacks. Neither feature substitutes `CpuBackendImpl` for the device backend:
CPU is the independently evaluated reference side of each comparison.

## Boundary

GRD-004 proves local device gradient recipes. It does not synchronize gradients
between ranks; DST-008 owns the typed DP=2 reduction and its two-host NCCL
evidence. Backend-local tape ownership remains GRD-006.
