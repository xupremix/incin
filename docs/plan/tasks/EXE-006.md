# EXE-006 - composable storage and descriptor execution interfaces

1. [x] Audit the RFC validation boundary, Appendix ownership table, current
   `Backend` supertrait and default unsupported methods, every backend/wrapper
   implementor, and every `SupportsDType` implementation.
2. [x] Add the minimal `Placement`/`Local` and `ExecutionContext<B>`
   foundations required for the stable D-020 encoding of D-001 and the exact
   D-002 signature, without implementing the distributed placement or
   execution-policy scope assigned to later tasks.
3. [x] Add backend-neutral `TensorHandle`, `StorageBackend`,
   `ExecutionRequest<'a, O, B>`, `Execute<O>`, and structured `BackendError`
   contracts; descriptor execution must accept sealed `Validated<O>` rather
   than a forgeable bare descriptor.
4. [x] Stage compatibility deliberately: keep the legacy `Backend` operation
   families callable until EXE-009, but do not add blanket `Execute<O>` or
   silent fallback implementations that would erase compile-time absence.
5. [x] Remove the default body from `SupportsDType<K>` and replace blanket or
   empty proofs with explicit, truthful CPU, CUDA, WGPU, dynamic-dispatch,
   tracing, dummy, and external-adapter implementations.
6. [x] Add semantic compile-pass/fail coverage proving that supported static
   dtype/backend pairs resolve, unsupported pairs fail by trait resolution,
   `Execute<O>` absence is a compile-time fact, and execution requests cannot
   contain unvalidated descriptors.
7. [x] Run the exact compile-test evidence plus no-default/core, default and
   optional backend checks, formatting, full workspace, diff-check, shape
   audit, and ledger validation.
8. [x] Record the staged-compatibility evidence and justified deviations before
   marking EXE-006 complete and activating EXE-007.
