# TUN-003 - General tuning service

1. [x] Implement disabled, heuristic, coordinated-warmup, and profile-guided
   policies without asynchronous background tuning.
2. [x] Carry static policy markers and a matching runtime `AutotunePolicy`.
3. [x] Carry static backend/scope contexts and a matching `Dyn` context which
   validates topology presence and time bounds.
4. [x] Filter determinism and transient workspace before any policy selects or
   measures a candidate.
5. [x] Validate cache key scope/backend/environment against the context.
6. [x] Revalidate every cached opaque winner against the current canonical
   legal candidate set.
7. [x] Issue one bounded epoch lease per key and make competing callers wait
   rather than measure twice.
8. [x] Release leases on cancellation, drop, and timeout.
9. [x] Require one local commit or one matching positive vote from every
   topology participant.
10. [x] Persist coordinated results through TUN-002 and consume profile
    databases without measuring.
11. [x] Accept DST-012's unanimous two-rank `CommittedCollectiveTuning` as the
    collective service commit proof.
12. [x] Add compile-fail evidence for static policy and scope mismatch.

The service suite covers all four policies, static/`Dyn` parity, filtering,
single flight, cancellation, expiry, two-rank votes, persistence, profile
fallback, untrusted winners, and two trybuild cases.
