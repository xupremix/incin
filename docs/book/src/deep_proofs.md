# Proofs: how claims are checked

Incin's design claim is that shape, dtype, and device rules are *proven*, not
promised - and the interesting engineering question is who checks each proof,
at which stage, and what happens when a check is missing. This chapter maps
the machinery: the stage inventory, the tests that keep contracts from rotting,
and the paranoid-validation escape hatch. Sources:
[`docs/audit/shape-proof-inventory.md`](../../../docs/audit/shape-proof-inventory.md),
`PROPOSALS.md` §1.2, `docs/FROZEN_FOUNDATIONS.md`.

## The five proof stages

The audit classifies every rule by the earliest stage at which it is actually
enforced in this tree:

| Stage | Name | Meaning |
|---|---|---|
| **T** | Type | Proven by trait resolution. An illegal program does not compile. |
| **L** | Lowering | Proven once, when an operation is resolved into a descriptor. |
| **B** | Binding | Proven when a resource is constructed, imported, or bound to a plan. |
| **N** | Native | Not re-proven; the executor trusts a sealed descriptor. |
| **U** | Unproven | Re-checked ad hoc at runtime, or rejected only when the backend fails. |

The single most important footnote to that table:

> **T is not a hardware claim.** `Cuda::new(0)` proves that the CUDA backend
> at ordinal 0 was *selected*, not that CUDA device 0 exists on the machine
> that runs the binary. Every physical-resource fact is inherently stage B or
> later; no amount of trait work moves it earlier.

A build script probing the build machine would be wrong for deployment,
cross-compilation, containers, and this repository's deliberate compile-only
CUDA CI path.

## Where each rule sits today

Selected rows of the inventory (regenerated by `tools/audit-shapes.sh --check`;
read the audit for the full tables):

| Rule | Today | Target |
|---|---|---|
| Rank compatibility, static dims | T | T |
| Static dimension equality | T | T |
| Broadcast / flatten / conv-pool output arithmetic | L | L |
| Overflow in numel / byte length | L | L |
| Named/runtime dimension equality | U → L | L |
| Reshape element-count equality | T | T |
| Static dtype/backend legality | U | T |
| Operation interface available | T (`B: Execute<O>`) | T |
| Physical device exists; storage matches metadata; alignment | B | B |

Two stories behind those rows are worth knowing because they shaped the
error contract.

**The `from_dyn().unwrap()` chains are closed.** The audit found 39 live
sites where typed shapes were erased to `Vec<usize>` and re-parsed with
`.unwrap()`, plus convolution/pooling geometry that silently zeroed runtime
spatial extents (a confirmed *wrong answer*, reproduced in execution, not
just a panic). The fixes made broadcast/matmul output computation fallible
(`SHP-004`) and replaced spatial formulas with a named checked sequence that
rejects zero strides by name (`SHP-005`). Latent wrong answers surfaced along
the way - broadcast resolving `size-1 vs size-0` as 1, matmul never checking
the contracted dimension at all - each worse than the panic it sat next to.
The generated block at the bottom of the audit pins all named chains at 0;
regression tests live beside the fixes.

**Operator panics are structural, deliberate API.** The remaining `panic!`
sites under tensor operators exist because `std::ops` signatures return
`Self::Output` and cannot return `Result`. They name the fallible method to
call instead ("call `.add()` directly instead of the operator"), emit only
bounded deterministic text, and are documented as the panic-on-error
convenience boundary in `docs/ERROR_CONTRACT.md`.

## What keeps it true

Claims here are enforced by tests, not memory. Three mechanisms do most of
the work.

**The frozen-foundations test.**
[`crates/incin-core/tests/frozen_foundations.rs`](../../../crates/incin-core/tests/frozen_foundations.rs)
fails if any path named in `docs/FROZEN_FOUNDATIONS.md` stops existing - so
that document cannot rot into a list of deleted files, and every row's "what
keeps it true" column stays checkable.

**The completeness proof.** In `incin-backends`, capability declarations are
grouped by rule *shape*, and one declaration feeds both the capability rows
and the executor set. `cpu::canonical`'s
`assert_every_advertised_row_executes!` turns an advertised row without an
`Execute<op::X>` behind it into a *compile error*. A capability claim and its
executor are the same edit; forgetting either half does not build.

**Generated evidence.** `docs/capabilities.md`,
`docs/OPERATION_SEMANTICS.md`, and the audit counts above are regenerated
from Rust source by tests; if a committed copy and a fresh regeneration
disagree, the test fails. Never hand-edit them - the docs index
([`docs/README.md`](../../../docs/README.md)) lists the regeneration
command for each.

## Paranoid validation

The normal contract is: executors trust sealed descriptors and do not
re-derive them. For testing, the `paranoid-validation` feature adds a
recomputation pass - explicitly *not* part of the release contract
(`PROPOSALS.md` §1.2.2 calls it "a testing aid"):

```rust,ignore
// crates/incin-core/src/exec/proof.rs (abridged)
#[cfg(feature = "paranoid-validation")]
impl<O: ExecutionDescriptor> Validated<O> {
    /// Re-derive the descriptor's own invariants and report disagreement.
    pub fn audit(&self) -> Result<(), ShapeError> { ... }
}

/// Assert a descriptor's invariants when `paranoid-validation` is on.
/// Expands to nothing otherwise, so an executor can call it on a hot path
/// and pay only in builds that asked to pay.
#[macro_export]
macro_rules! paranoid_audit {
    ($validated:expr) => {{ ... }};
}
```

If `audit()` ever fails, a descriptor reached a backend without going through
a checked constructor - a bug in the lowering layer, which is why the
panicking form treats it as unrecoverable rather than returning an error to
a caller.

## Provenance, again

One last piece connects back to [type semantics](./deep_type_semantics.md): the
proof level recorded in a `Validated<O>` comes only from `ShapeEvidence::of::<S>()`
(read off a real shape type) or `ShapeEvidence::dynamic()` (claims nothing).
There is no constructor taking a bare `ProofLevel` from a caller, because a
caller who could assert `Static` for a runtime shape would be handing kernels
a constant that does not exist. A foreign `Shape` impl can overstate its own
`PROOF` - silence defaults to `Dynamic`, so nothing is credited without
evidence - but nobody can assert a level with no type behind it at all.

## Reading the evidence yourself

```bash
# regenerate + verify the proof-site inventory
tools/audit-shapes.sh --check

# the generated support matrix and per-operation semantics
$PAGER docs/capabilities.md docs/OPERATION_SEMANTICS.md

# the panic classification archive referenced by the error contract
$PAGER audit-evidence/FND-003/panic-classification.md
```

A claim in any of these documents that is not reproducible from
`audit-evidence/` logs should be treated as unproven -
[`docs/README.md`](../../../docs/README.md)'s rule, and a good habit to
import.
