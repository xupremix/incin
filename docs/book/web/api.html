What a row here does and does not mean

A row is a capability declaration, not a test result. It says what this build of Incin would run if the device were present — the registry is queried from the same declaration that generates this page, and every advertised operation must also satisfy the compile-time Execute<O> contract.

It is not evidence that the kernel is correct. The runtime suites exercise representative and boundary behaviour; they do not execute every dtype, layout, rank and training boundary shown below. Closing that gap is tracked as open work rather than claimed as done — see issue #83, a CPU-oracle conformance harness for advertised capabilities.

The distinction is why this page exists. A support matrix that cannot tell you which half you are reading is the kind of claim nobody checks.

Storage is a block encoding, not a scalar width. A dtype declares how many logical values sit in a block, how many bytes that block costs, and its alignment — so a type is free to pack. q8_0 already does: 32 values in 34 bytes, 8.5 bits each, because a block carries one f16 scale alongside its 32 quantized bytes.

bool does not. It is one byte per element, so a boolean mask costs eight times what its information content needs. A bit-packed boolean is expressible in this model today — it would be a block of 8 values in 1 byte — and the gap is not the encoding but everything downstream of it: strides are counted in elements and resolved to byte offsets, so a sub-byte element makes every stride computation, every view, and every kernel index a bit address. That is a change to the layout model and to each backend's kernels, not to this table.

What each backend advertises across the catalog: how many operations, how many run a kernel of their own, how many accept a strided operand, and which element types it handles anywhere.

A layout is what a tensor's type claims about the memory behind it. An operation that allocates states what it allocated, so a result can be reshaped as a view without a runtime stride scan. The claim is checked where it is made, which is why ChannelsLast is deliberately not Contiguous.

    Reading a row

    Element types are the dtypes the rule covers. A dtype absent from every rule for an operation is refused by the registry — which is what lets a planner ask before it allocates, rather than discovering it from a trait method that errors at run time.

    Layouts are LayoutClass values. contiguous is dense row-major; strided means the kernel handles a non-dense view without a copy. The gap between CPU and CUDA here is real, and a kernel that exists while its row says contiguous is unreachable through the public API.

    Rank is the tensor rank the rule accepts; any is an unbounded rule. Training says whether the rule also covers the backward pass — a rule marked no still runs under inference.
