== Release identity ==

Command: python3 tools/release-preflight.py --tag v0.1.0 --base-ref HEAD
Result: "release preflight passed". Run against a throwaway local tag that was
deleted immediately and never pushed.

Negative check: the same command with the tag one commit behind HEAD was
refused with "checkout is <head>, but v0.1.0 resolves to <other>". The gate
verifies the exact commit being released, not merely a well-formed tag name.

Command: python3 tools/release-preflight.py --tag v0.1.0 --base-ref master
Result: refused with "release tag 'v0.1.0' is not reachable from master".
This is the base-ref the release workflow actually passes (as origin/master),
and the earlier --base-ref HEAD run is trivially satisfied and does not
exercise the ancestry rule. The candidate sits on integration/0.1.0 while
master is still at 094bb484. See the summary for what this means for tagging.

== Not run, and why ==

Command: cargo clippy --workspace --all-targets --all-features -- -D warnings
Not run. --all-features enables the CUDA, Metal, and WGPU stacks together;
this machine has no accelerator toolchains or devices, and the workspace
deliberately keeps the accelerator example crates out of default-members for
this reason. The CPU clippy gate above ran with -D warnings and passed, and CI
runs the accelerator lints in their own jobs. This was recorded as unavailable
rather than substituted with a narrower run reported as if it were the same
command.

Command: MSRV verification at 1.88
Not run locally. The pinned toolchain is 1.97.1 and CI holds the MSRV in a
dedicated job.

Miri, AddressSanitizer, LeakSanitizer, ThreadSanitizer: not run. They are the
soundness job in CI (tools/soundness.sh) and need a nightly toolchain plus
sanitizer runtimes.

Hardware execution on CUDA, Metal, or WGPU devices: not run. No device present.
