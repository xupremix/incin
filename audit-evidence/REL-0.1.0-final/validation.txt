== Checks previously recorded as unavailable, and now actually run ==

An earlier draft of this bundle listed the following three as unavailable in
this environment. That was wrong in all three cases, and testing the assumption
rather than restating it found three real defects. They are recorded here as
run.

Command: bash tools/soundness.sh
Result: exit 0 on the final candidate. Five checks: miri on incin-core, miri on incin-backends,
AddressSanitizer baseline, AddressSanitizer with +avx2, and ThreadSanitizer on
parallel AVX2 initialization. Miri runs under Tree Borrows
(-Zmiri-tree-borrows) on the pinned nightly-2026-07-28, which carries the miri
component locally.

Command: RUSTUP_TOOLCHAIN=1.88.0 cargo check --workspace --all-targets --locked
Result: exit 0. This is the command the MSRV job runs, at the declared MSRV,
with RUSTUP_TOOLCHAIN overriding the repository's 1.97.1 pin the same way CI
does.

Command: cargo clippy --workspace --all-targets --all-features -- -D warnings
Result: exit 0, after three fixes. It does not need accelerator hardware: the
CUDA, Metal, and WGPU code typechecks locally without a device, and only
execution needs one. Attempting it surfaced:

  1. The CUDA and Metal arms of the addition benchmark in
     crates/incin/benches/baselines.rs called .unwrap() on `&input + &input`,
     which returns a tensor and not a result. Neither arm had ever compiled.
     The CPU and WGPU arms of the same benchmark were already correct.
  2. Four unsafe blocks in the incin-data hub tests had no `// SAFETY:`
     comment. One carried its reasoning under a `SAFETY-equivalent:` heading
     the lint does not recognise; three had none.
  3. A public struct in the distributed macro test suite had no doc comment.

None of the three is reachable from the CPU-only lint job, because the targets
involved are either feature-gated or not built with --all-targets.

== Still not run, and why ==

Hardware execution on CUDA, Metal, or WGPU devices: no device is present. The
accelerator code is compile-checked and lint-clean here, and that is the only
claim made for it.

Feature powerset (cargo hack --feature-powerset): CI runs this as its own job
across incin-core, incin-macros, and incin-diagnostics. The supported feature
contract matrix, which is the curated subset, does run here and passes across
31 rows.
